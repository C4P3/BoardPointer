# BoardPointer

Wii バランスボードを Windows のマウスとして使うためのツールです。

椅子に座ったまま足先で、あるいは立って体重移動で、カーソルを動かせます。重心の位置を
カーソルの**速度**に写すので、足を中立に戻せば止まります。

```
  実機 ─┐
 CSV ──┼─→ 重心を出す ──────→ カーソル速度に写す ──→ Windows に送る
  合成 ─┘   較正・ゼロ点・          可動域で正規化・        端数を溜めて
             フィルタ・在席判定       デッドゾーン・曲線      SendInput
```

## 必要なもの

- Windows 10 / 11（x64）
- Bluetooth
- Wii バランスボード（RVL-021 など）と電池
- 配布ビルドを使う場合、.NET のインストールは不要です

## 使ってみる

**実機が無くても動きます。** まず手触りを見るなら:

```bash
BoardPointer.Viewer.exe --synthetic
```

合成データが流れて、重心の点が動きます。つまみを触ったときの反応もそのまま見られます。

### 実機で使う手順

1. **ボードをペアリングする。**
 Windows の設定から追加するのが確実です。PINコードの入力をスキップするため、以下の手順でコントロールパネルからデバイスを追加してください。
 Windows 10 の場合:
 「コントロール パネル」を開き、「ハードウェアとサウンド」内にある [デバイスの追加] をクリックします。
 Windows 11 の場合:
 Windowsの設定から [Bluetooth とデバイス] > [デバイス] を開きます。一番下までスクロールして [デバイスとプリンターのその他の設定] をクリックするとコントロールパネルが開くので、左上の [デバイスの追加] をクリックします。
※アプリ内の [ペアリング (SYNC)] でも可能です（電池蓋の中の SYNC ボタンを押す）。
2. **[接続]** を押す。青いLEDの点滅が消えて点灯に変われば成功です。
3. 姿勢に合わせて**モード**（立ち / 座り・足先）を選ぶ。
4. **足をボードから離して** から **[荷重ゼロ点 (降りて3秒)]**。
5. 操作する姿勢に戻り、**力を抜いて** **[重心の原点 (3秒)]**。
6. **[可動域キャリブレーション (12秒)]** を押し、足先で大きく円を描くように前後左右いっぱいまで動かす。
7. **[マウス出力 開始]** か **F9**。

**F9 はグローバルショートカットです。** マウス出力中はカーソルが足に取られて窓のボタンを
押しに行きにくくなるので、フォーカスがどこにあっても止められる経路を必ず用意しておいてください。

## つまみの意味（数式つき）

生の値からカーソルの速度まで、一本の式で繋がっています。順番に見ると、どのつまみが何を
変えるのかが分かります。

### 1. 生値 → 荷重

4隅のセンサーは整数の生値 `rᵢ`（i = 前右, 後右, 前左, 後左）を返します。ボード自身が持っている
工場出荷較正（0kg / 17kg / 34kg のときの生値）で kg に直します。

```
wᵢ = 区分線形補間(rᵢ)          [kg]
```

さらに、床の傾きや脚の高さのばらつきを消すためにゼロ点 `zᵢ` を引きます。

```
w'ᵢ = max(0, wᵢ - zᵢ)
W   = Σ w'ᵢ                     ← 合計荷重
```

### 2. 荷重 → 重心（COP）

重心は各隅の荷重の按分です。`A` はセンサー間の距離（左右 433mm、前後 238mm）。

```
x = (A_x / 2) · ((w'前右 + w'後右) − (w'前左 + w'後左)) / W     右が正
y = (A_y / 2) · ((w'前左 + w'前右) − (w'後左 + w'後右)) / W     前が正
```

**合計 `W` で割っている**のが、このあと何度も効いてきます。

> **重心のノイズと分解能は、合計荷重に反比例します。**
>
> ```
> 重心の分解能 [mm] = (A_x / 2) · (1カウントあたりの kg) / W
> ```
>
> 実測のボードで 1 カウント ≒ 9.7 g。立位（60kg）なら 0.03 mm/count ですが、座って足を置いた
> 状態（15kg）では 0.14 mm/count、2kg まで落ちると 1.05 mm/count になります。
> **値が飛び飛びに見えるときに疑うべきは合計荷重です。**

中立姿勢を原点に移します。`(x₀, y₀)` は [重心の原点] で測った値です。

```
x' = x − x₀,   y' = y − y₀
```

### 3. フィルタ

1ユーロフィルタ（Casiez, Roussel, Vogel 2012）を通します。ポインティング入力のために
作られたフィルタで、**推定した速度でカットオフ周波数を動かす**のが要点です。

```
カットオフ = min-cutoff + beta · |推定速度|
```

- **min-cutoff** を下げる → ゆっくり動かしているときが静かになる（が、動き出しが遅れる）
- **beta** を上げる → 速く動かしたときの遅れが減る

静止しているつもりでも重心は止まりません（人間の立位は閉ループの姿勢制御なので）。
実測で、15kg で静止しているときのサンプル間の重心の動きは中央値 1.1mm ありました。

### 4. 可動域で正規化

前後と左右で届く距離は違いますし、前後も対称になりません。ここで方向ごとに割って、
下流が扱うのを無次元の円だけにします。

```
nx = x̂ / (x̂ ≥ 0 ? 右可動域 : 左可動域)
ny = ŷ / (ŷ ≥ 0 ? 前可動域 : 後可動域)
ρ  = √(nx² + ny²)
```

可動域の4つの数字は感覚で決めるものではなく、**キャリブレーションが実測で埋めます**。

この分け方のおかげで、実空間でのデッドゾーンは円ではなく**楕円**になります（揺れの大きさ自体が前後と左右で違うので、そのほうが正しい）。しかも斜め方向で軸スナップが出ません。

### 5. 応答曲線 → 速度

```
t = clamp((ρ − デッドゾーン) / (フルスケール − デッドゾーン), 0, 1)
s = 最大速度 · t^指数                                        [px/秒]
```

- **デッドゾーン**: ここまでは速度 0。可動域に対する割合なので、人や姿勢が変わっても意味が同じ
- **指数**: 1 で直線。上げるほど中心付近が緩く（狙いやすく）、端が急に（速く）なる
- **最大速度**: フルスケールでの速度

縁で 0 から連続に立ち上がるので、境界がばたついてもカーソルは飛びません（段ごとに定速にすると、
境界を跨ぐたびに速度が階段状に飛んで明確に気持ち悪くなります）。

### 6. 荷重（踏み込み／脱力）を混ぜる

合計荷重 `W` を、重心とは別の軸として使えます。基準 `W_rest` は [重心の原点] を測ったとき
（力を抜いた姿勢）の合計荷重です。

まず `W` を均します。重心は1ユーロフィルタを通っていますが、合計荷重は素のままだと 100Hz の
ノイズをそのまま受け、倍率が毎サンプル跳ねて曲線グラフの縦方向が暴れます。

```
W̄ ← W̄ + (W − W̄) · (1 − exp(−Δt / 時定数))      ← 指数移動平均 (EMA)
```

**単純移動平均ではなく EMA です。** 実測の記録で同じ平滑度に揃えて比べると、遅れが約1/3で済みます。

| 平滑度（比のジッタ） | 移動平均 | EMA |
|---|---|---|
| 0.0007 倍/サンプル | 20サンプル → **150ms 遅れ** | 50ms → **45ms 遅れ** |
| 0.0005 倍/サンプル | 50サンプル → **375ms 遅れ** | 100ms → **120ms 遅れ** |

移動平均（箱型）は群遅延のわりに高周波の落ち方が悪いためです。加えて EMA は状態が1つで済み、
バッファが要りません。1ユーロフィルタを使わないのは、ここが閾値判定だからです。速さで実効的な
平滑度が変わると作動点が微妙にずれます。位置（カーソル）には適応が効きますが、ゲートには
素直な一次遅れが合います。

既定は **100ms**。実測で、倍率の1サンプルあたりの変化が p95 で `0.1204 → 0.0270`（約4.5分の1）に
なりました。強くしすぎると比の可動域そのものが痩せる（0.85〜1.09 が 400ms では 0.90〜1.06）ので、
閾値を置ける幅を食わない範囲に留めてあります。

この平滑化を使うのは**荷重の軸だけ**です。重心は同じサンプルの合計で割って初めて意味を持ちますし、
在席判定は別に時間ヒステリシスを持っているので、どちらもここを通しません。

```
p = W̄ / W_rest                                                    ← 荷重比
u = clamp((p − 作動) / (振り切り − 作動), 0, 1)                     ← 正規化
g = 作動側の速度 + (振り切り側の速度 − 作動側の速度) · u^荷重の指数   ← 速度モード
g = (作動側に届いていれば 1、なければ 0、ヒステリシス付き)            ← クラッチ
g = 1                                                               ← 使わない
```

**向きは2つの閾値の大小だけで決まります。** 全開側を作動側より小さくすれば「軽くするほど速い」、
大きくすれば「踏み込むほど速い」。分子と分母の符号が一緒に反転するので、同じ式がどちらでも成立します。

既定は**軽くする向き（作動 0.97 → 全開 0.85）**です。実測では、座って足先で操作したときの
合計荷重は安静時の **0.82〜1.13 倍**の範囲でしか動きませんでした。踏み込む側は椅子を押し返す
必要があって可動幅が取りにくく、足を浮かせ気味にする側のほうが幅も出ます。

#### 閾値は [荷重の範囲を測る (8秒)] で決めてください

感覚で決めるものではありません。既定値のまま実測の記録を流すと、**81% の時間が倍率 0 に張り付き、
全開には一度も届いていませんでした**（2つの記録とも 0.0%）。「全力が分かりにくい」のは、体感した
ことがないからです。

ボタンを押して「足を一番軽くする・一番踏み込む」を数回繰り返すと、分布から作動と振り切りを置きます。
よく動かしたほうの向き（軽くする／踏み込む）も自動で選びます。

実測の記録での効果:

| 設定 | 動いていた時間 | 速度 p95 |
|---|---|---|
| 既定（作動0.97→全開0.85） | 11.5% | 2 px/s |
| 測定が置く値（0.99→0.88） | 24.8% | 16 px/s |
| ＋ 荷重の指数 0.6 | 24.8% | 37 px/s |

#### 荷重の指数

重心側の指数と同じ役割で、作動から全開までの配り方を決めます。1 未満にすると少し動かしただけで
倍率が立ち上がります。ただし効き幅は限定的で、**「倍率 0 に張り付く」問題そのものは閾値の位置で
決まります**。まず範囲を測ってください。

#### 出力の両端 — 増える方向にも減る方向にも設定できます

**作動側の速度**と**振り切り側の速度**で、荷重が速度に与える範囲を決めます。**どちらが大きくても
かまいません。**

| 作動側 → 振り切り側 | 挙動 |
|---|---|
| **100% → 25%**（既定） | 普段は通常速度、**足を浮かせると 25% に落ちて細かく狙える** |
| 100% → 0% | 普段は通常速度、浮かせると止まる |
| 0% → 100% | 普段は止まっていて、浮かせると動き出す |

既定が1番目なのは、座位で噛み合うからです。座って足を浮かせる／踏み込む動作は**本質的に 0/1 に
近い**もので、途中の量を保持し続けるのは位置の手がかりが無い等尺性の課題です。連続量として使おうと
すると生理に逆らいます。確実にできる動作（浮かせる）を確実な切り替えとして使い、連続量は重心に
任せる、という分担にすると素直に動きます。

また、踏み込む側は椅子を押し返す必要があって可動幅が取りにくく、足を浮かせる側のほうが幅が出ます
（実測で -18% 対 +13%）。

実測の記録での違い:

| 設定 | 動いていた時間 | 速度の中央値 |
|---|---|---|
| 0% → 100% | 24.8% | 0 px/s |
| **100% → 25%**（既定） | **93.0%** | **384 px/s** |
| 100% → 0% | 91.0% | 384 px/s |

> 状態表示に、今の設定が結局どう振る舞うのかが1行で出ます:
> `浮かせると 100% → 25% (遅くなる)`

> **状態表示を見てください。** 今の比と直近5秒の範囲、実際の倍率、そして設定の意味が並びます
> （`荷重 1.02 倍 (直近 0.88〜1.13)` / `倍率 0.39` / `浮かせると 100% → 25% (遅くなる)`）。
>
> - 基準荷重が未測定だと比が出せないので、**荷重モードは自動的に無効になります**
> - **安静時 (1.00) が作動〜全開の外にある**と、倍率は常に端に張り付いて効きません。
>   両方の閾値を 1.00 より下（あるいは上）に置くと起きます。この場合も警告が出ます

### 7. カーソルへ

```
v  = s · g
vx = v · nx / ρ
vy = −v · ny / ρ          画面のYは下が正なので符号を反転
```

速度はフレームごとに積分され、端数は次回に持ち越されます。

```
累積 += v · Δt
送る量 = trunc(累積)
累積 −= 送る量
```

**この持ち越しが無いと低速域が丸ごと死にます。** 100Hz なら 1サンプルあたり 1px に満たない
速度、つまり **100 px/秒 未満が毎回切り捨てられて永久に 0** になります。

### 右側のグラフの読み方

- 太い水色の線が**今の実効カーブ**（荷重の倍率 `g` を掛けた後）
- 荷重モードで倍率が 1 未満のとき、薄い細い線が**掛ける前の形**として一緒に出ます
- 橙色の丸が**今の自分の位置**。縦軸の高さが、実際に出ている速度です

## ゼロ点は2種類あります

混ぜると壊れます。

| | いつ測るか | 何を消すか |
|---|---|---|
| **荷重ゼロ点** | ボードに**何も載っていない**状態 | 床の傾き、脚の高さのばらつき |
| **重心の原点** | **操作する姿勢のまま**力を抜いた状態 | その人の中立姿勢 |

**荷重ゼロ点を足を載せたまま測ると壊れます。** 足の重さごと差し引かれて合計荷重がほぼ 0 になり、
重心は合計で割る比なので端（±216.5mm）まで振り切れます。症状は「少しずれる」ではなく
「重心が使いものにならない」です。測定中に 3kg 以上載っていたら警告が出ます。

中立姿勢を消したいときに使うのは **重心の原点** のほうです。

**原点は操作中にもずれます。** レート制御では原点のわずかなずれが恒常的なカーソルの流れに
なるので、対策が2つあります。

- **F12（既定）で今の位置に即座に合わせ直す。** 「カーソルが一方向に流れ始めた」と感じた瞬間に押す
- **[原点を自動追従]** を入れる。操作していない間だけ、時定数 20 秒でゆっくり寄せる

### 椅子に座って足先で操作する場合

モードを **座り・足先** にしてください。立位との違いは姿勢ではなく**荷重の桁**にあります。

この姿勢では脚の重さ（実測で 12〜15kg）がボードに載りっぱなしで、操作そのものはその上に乗る
数 kg の重心移動として出ます。立位の既定値（在席閾値 15kg）のままだと、脚の重さがちょうど
閾値付近をうろついて在席判定がちらつきます。座りモードは在席を 2.5/1.2kg まで下げ、フィルタを
少し強くします。

## 記録と解析

**`BoardPointer.Replay.exe` は独立したコマンドライン解析ツールです。** Viewer から呼ばれる
ものではありません。Viewer の CSV 再生（[CSVを再生...] ボタン）は Viewer 自身の機能で、
両者は別物です。

| | 役割 |
|---|---|
| `BoardPointer.Viewer.exe` | 実際に使うアプリ。接続・可視化・記録・マウス出力。CSV の再生も自前で持つ |
| `BoardPointer.Replay.exe` | 記録した CSV を流し直して**数字を出す**CLI。チューニングの裏取り用 |

Viewer で [記録開始] すると、`debug/session_*.csv` に生データが貯まります。それを Replay に
渡すと統計が出ます。

```bash
BoardPointer.Replay.exe debug/session_20260919_172720.csv --seated --center-seconds 2
BoardPointer.Replay.exe debug/session_20260919_172720.csv --seated --mouse --pressure clutch
BoardPointer.Replay.exe --synth debug/synth.csv          # 実機なしで試すデータを作る
BoardPointer.Replay.exe --help
```

### オフラインで詰められること／詰められないこと

レート制御は**閉ループ**です。記録の中の足の動きは、そのとき見えていたカーソルに反応した結果
なので、別の設定で流し直しても同じようには動きません。**操作感そのものは実機で触るしか
ありません。**

`--mouse` で確かめられるのは、閉ループに依らない部分だけです。

- 無反応な範囲が実寸で何 mm になるか
- 静止しているつもりの時間にカーソルが止まっているか
- 最大速度に届くか（可動域と曲線が噛み合っているか）
- 低速域が死んでいないか（端数の持ち越しの検査）
- 荷重比が実際にどこまで出ていたか（閾値が到達可能か）

### 記録するのは生値だけです

kg も重心もフィルタ後の値も CSV に書きません。派生値を混ぜると、パイプラインを直した瞬間に
過去の記録が「古いパイプラインの出力」になって比較できなくなります。派生値が見たいときは
`--out` で毎回作り直してください。

もうひとつ、**パイプラインは実時間に依存しません**。フィルタの `Δt` も在席判定のタイマーも、
壁時計ではなくサンプルのタイムスタンプから出しています。だから同じ CSV を同じ設定で流せば、
ライブ実行と同じ結果になります。

## 設定・ショートカット・常駐

設定は `%LOCALAPPDATA%\BoardPointer\settings.json` に自動保存されます（終了時と、可動域を
測り終えた直後）。手で開いて直せます。

**引き継ぐものと、毎回測り直すものを分けてあります。**

| | 何に依存するか | 扱い |
|---|---|---|
| 曲線・閾値・モード | 好み | **保存** |
| 可動域・基準荷重 | その人の体と姿勢 | **保存**（測るのに12秒かかる） |
| 重心の原点 | その日の足の置き場所 | **毎回測る**（3秒） |
| 荷重ゼロ点 | ボードの設置場所 | **毎回測る**（3秒） |

後ろ2つを復元すると、ボードが少し動いただけでずれた原点から始まり、しかも「なぜかカーソルが
流れる」という分かりにくい形で症状が出ます。3秒で測り直せるものを危険な形で引き継ぐ理由が
ありません。

### ショートカット

「設定」タブで変更できます。枠をクリックしてからキーを押してください（Esc で解除）。

| 動作 | 既定 |
|---|---|
| マウス出力 入/切 | F9 |
| 左クリック | F10 |
| 右クリック | F11 |
| 重心の原点を今に合わせる | F12 |

**「マウス出力 入/切」は必ず割り当てておいてください。**

クリックは今キーボードから呼んでいますが、送っている入力自体は本物のマウスと同じです。

### 常駐

窓の × はトレイへの格納で、終了しません（「設定」タブで切り替え可）。本当に終わるのはトレイの
**[終了]** から。`--tray` を付けると窓を出さずトレイだけで始まります。

トレイの右クリックから **接続 / マウス出力の入切 / 荷重ゼロ点 / 重心の原点 /
原点を今に合わせる** ができます。常駐の価値は「起動しっぱなしにできる」ことより、
**窓を出さずに測り直せる**ことのほうが大きいです。マウス出力中はカーソルが足に取られるので、
窓のボタンを押しに行くのが難しくなります。

アイコンの色が状態を示します（灰 = 未接続 / 水色 = 接続中 / 橙 = マウス出力中）。

### 起動オプション

| | |
|---|---|
| `--synthetic` | 合成データで起動（実機不要） |
| `--replay <CSV>` | 記録した CSV を再生しながら起動 |
| `--seated` | 座り・足先モードで起動 |
| `--tray` | 窓を出さずトレイだけで起動 |

## 繋がらないとき

Windows の Bluetooth スタックは癖が強く、ここが一番つまずきます。

**まず試すこと**

1. 電池を確認する（弱いと繋がらない・すぐ切れる）
2. Windows の設定でボードを一度削除し、追加し直す
3. Viewer の [接続] を押す。ステータス欄に原因が出ます

**症状別**

| 症状 | 見るところ |
|---|---|
| ボードが見つからない | ペアリングできているか。Windows の設定で「Nintendo RVL-...」が見えるか |
| 青いLEDが点滅し続ける | 接続できていません。[接続] が成功すると点灯に変わります |
| 数分で切れる | キープアライブは入れてありますが、電池が弱いと切れます |
| 「工場較正を読めなかった」と出る | 一度でも読めていれば保存された値を使います。[停止] → [接続] で読み直せることがあります |
| 荷重が kg ではなく変な値 | 荷重ゼロ点を取ってください。較正が無い場合、ゼロ点が無いと荷重が確定しません |
| 重心が端まで飛ぶ | 荷重ゼロ点を足を載せたまま測っていませんか（上の「ゼロ点は2種類」参照） |
| 荷重モードにすると動かない | 基準荷重が未測定です。[重心の原点] を測ってください |
| ゆっくり動かすときだけ効かない | 端数の持ち越しの不具合です。`Replay --mouse` で検査できます |

**アプリ内 SYNC ペアリングについて**

アプリ内の SYNC ペアリングは、PIN を使わない手口を使っています。そのため Windows に残る
プロファイルが `Authenticated = false` になり、**OS のバックグラウンド自動再接続が効きません**。
この方法でペアリングした場合、毎回 SYNC が必要です。

Windows の設定から普通に追加した場合に同じ制約になるかは未確認です。電源を入れ直して [接続] が
通るなら、そちらのほうが運用は楽です。

**自己診断**

```bash
BoardPointer.Replay.exe --bluetooth-selftest   # Bluetooth ライブラリが読めるか
BoardPointer.Replay.exe --mouse-selftest       # カーソルが指示どおり動くか
```

## サポートの範囲

個人が趣味で作っているツールです。以下をご理解ください。

- **Bluetooth の環境依存の問題には対応できないことがほとんどです。** Bluetooth アダプタ、
  ドライバ、Windows のバージョン、他の常駐ソフトの組み合わせで挙動が変わり、手元で再現
  できないものは直しようがありません。
- **動作確認は限られた環境でしか行っていません。** 特にマルチモニタ、高DPI、複数の
  バランスボードといった構成は未検証です。
- 機能追加の要望には基本的に応えられないです。MIT ライセンスにしているので、**フォークして好きに改造してください。**
- Issue を立てる場合は、**再現手順・環境・記録した CSV・`--bluetooth-selftest` の出力**を
  添えてください。テンプレートを用意してあります。これが無いと、ほとんどの場合お手上げです。

## 仕組みのメモ

自力で再発見すると時間が溶ける部分です。調査済みなので、同じところで悩まないでください。

- **ボードは PIN を使いません。** Windows の標準的な PIN/パスキー認証APIを呼ぶと失敗するか
  ハングします。正解は SYNC 中に discover したデバイスに HID サービスを有効化するだけ。
- **青いLEDの点滅は自分で止めます。** ペアリングが済んだだけでは点滅し続けます。
  プレイヤーLEDのレポート（`0x11`、LED1 = `0x10`）を1本投げると点灯に変わります。
- **キープアライブが要ります。** ホストが何も書き返さないと、データを流している最中でも
  ボードは数分で勝手に切断します。5秒ごとにステータス要求（`0x15`）を投げています。
- **起動シーケンスの順序。** `0x15` → `0xA400F0=0x55` → `0xA400FB=0x00` → 較正読み出し →
  `0x12 0x04 0x32`。較正テーブルは拡張機能レジスタを初期化したあとでないと読めません。
- **較正の読み出しは時々すべります。** 初期化からやり直して3回まで試します（待ちは 120ms）。
- **Windows のポインタ加速を迂回しています。** 相対移動で送ると「ポインターの精度を高める」を
  通り、設計した応答曲線の上からもう一本カーブがかかります。現在位置を読んで足した先へ
  **絶対座標**で送ることで加速を迂回しています。物理マウスと同時に使っても喧嘩しません。

### 工場出荷較正

ボード自身が 4 センサーぶんの「0kg / 17kg / 34kg のときの生値」を持っていて、拡張機能レジスタ
`0xA40024` から 24 バイトで読めます。

**工場較正はボードに焼かれた定数です。** 実測でも別セッション間で1ビットも変わりませんでした。
一方で読み出しは接続のたびに成否が揺れます。変わらない値を毎回取りに行って、失敗したら精度を
捨てるのは筋が悪いので、一度読めたら `%LOCALAPPDATA%\BoardPointer\calibration.txt` に保存し、
次に読めなかったらそれを使います。

過去の記録から取り込むこともできます。

```bash
BoardPointer.Replay.exe --import-calib debug/session_xxx.csv
```

保存も記録も無い場合は**公称ゲイン**（103.5 カウント/kg）に落ちます。ゲインはボードの機構で
決まるので個体差が小さく（実測の4隅で 101.7〜107.4）、原点は荷重ゼロ点が消してくれるため、
これでも kg で決めた閾値は実用になります。ただし荷重ゼロ点を取っていることが条件です。

なお、参考にした WiiFitToVRC は工場較正を読まず、ゼロ点を引いた「各隅の割合」で足踏みを分類
しています。離散イベントの分類ならそれで足りますが、**重心を座標として使うならセンサーごとの
ゲイン差がそのまま座標の歪みになります**。

## 開発

```bash
dotnet build BoardPointer.sln
dotnet run --project src/BoardPointer.Viewer -- --synthetic
```

配布ビルド:

```powershell
.\publish.ps1
```

`publish\` に自己完結の単一 exe が2つ出ます（Viewer 約69MB、Replay 約34MB）。

指定しているオプションには理由があります。

- **`PublishTrimmed` は切ってあります。** `InTheHand.Net.Personal.dll` は .NET Framework 時代の
  アセンブリで、WinForms はリフレクションに依存します。どちらもトリミングで壊れます。
- **圧縮**で約140MB→70MB。
- **ネイティブ DLL の内包**が無いと、exe の隣に WPF 系の DLL が5個並びます。

`publish.ps1` は最後に自己診断を叩きます。単一ファイル化で最も怪しいのは .NET Framework 時代の
32feet.NET が読めるかどうかで、しかも**失敗しても SYNC ペアリングを押すまで誰も気づきません**
（ボードを繋ぐ側は P/Invoke だけで動くため）。実際この検査で
`System.Configuration.ConfigurationManager` の参照漏れが見つかりました。

### 構成

| 場所 | 役割 |
|---|---|
| `src/BoardPointer.Core/Hid/` | HID の口。起動シーケンス、キープアライブ、工場較正 |
| `src/BoardPointer.Core/Bluetooth/` | SYNC ペアリング |
| `src/BoardPointer.Core/Sampling/` | サンプル源の抽象（実機／CSV再生／合成） |
| `src/BoardPointer.Core/Recording/` | 生CSVの読み書き |
| `src/BoardPointer.Core/Pipeline/` | 較正・ゼロ点・重心・フィルタ・在席判定 |
| `src/BoardPointer.Core/Mapping/` | 可動域・応答曲線・カーソル速度・SendInput |
| `src/BoardPointer.Core/Settings/` | 設定とショートカットの保存 |
| `src/BoardPointer.Viewer/` | 可視化、記録、つまみ、常駐 |
| `src/BoardPointer.Replay/` | 記録を流し直して統計を出すCLI |

### この先（まだ無い部分）

- **クリックを足の動作に移す。** いまはキーボード。荷重の軸はもう通っているので、タップ
  （荷重の急変）を拾うか、クラッチ + dwell にするか。どちらも既存の信号だけで作れます
- **応答曲線のエディタ。** いまは指数1つ。制御点を打てるようにするなら、単調性を保つ補間で
- **仮想コントローラー出力。** ViGEmBus 経由の仮想 Xbox 360。多くのゲームは `SendInput` の
  合成入力を無視するので、ゲームで使うならこちらが要ります
